Academy Timetable - Complete Project Information
================================================
App Name  : Guru Aanklan Academy Timetable
Deployed  : https://time-table-guru.netlify.app  (frontend)

=======================================================
1. TECH STACK
=======================================================

Frontend (client/)
  - React 18 + Vite (SPA, no router library -- uses manual history API)
  - Tailwind CSS for utility styling
  - Zustand for global auth state (useAuthStore)
  - TanStack React Query v5 for server state, caching, and mutations
  - Axios for HTTP (with JWT interceptor + localhost fallback to Render)
  - date-fns for date utilities
  - Hosted on Netlify (client/dist/_redirects for SPA fallback)

Backend (server/)
  - Node.js (ESM modules) + Express 4
  - MongoDB Atlas (Mongoose 8) via SSL connection string
  - Puppeteer for headless PDF generation
  - docx (v9) for Word document generation
  - Archiver (v5.3.2, pinned) for ZIP exports
  - express-validator for route-level input validation
  - bcryptjs (cost 12) for password hashing
  - jsonwebtoken (2-hour access tokens, HS256)
  - helmet for HTTP security headers
  - cors for origin allowlist
  - express-rate-limit for rate limiting
  - express-mongo-sanitize for NoSQL injection prevention
  - Hosted on Render


=======================================================
2. DATA MODELS (Mongoose)
=======================================================

User
  - name (String)
  - email (String, unique, lowercase)
  - passwordHash (String, bcrypt cost 12)
  - role (enum: "user" | "admin")
  - lastLoginAt (Date)

Teacher
  - name (String, unique, case-insensitive dedup)
  - code (String, unique, auto-generated from initials e.g. "AB")
  - subject (String)
  - chapters: [{ chapterNumber, title, plannedHours,
      branchCompletions: [{ branch, isCompleted, completedAt }],
      batchCompletions:  [{ branch, batch, isCompleted, completedAt }] }]
  - color (String, hex, auto-assigned random if not provided)
  - allowScheduleOverlap (Boolean, default false)

Branch
  - name (String, unique)

Batch
  - name (String)
  - branch -> Branch (ref)

TimeSlot
  - date (Date)
  - startTime (String, normalized e.g. "09:00")
  - endTime (String)
  - teacher -> Teacher (ref, nullable for test slots)
  - batch -> Batch (ref)
  - topic (String)
  - subject (String)
  - chapterNumber (String)
  - slotType (enum: lecture | lecture-theory | lecture-mcq | test | mcq | revision | coverup)
  - status (enum: scheduled | ongoing | completed | canceled)
  - cancelNote (String)
  - canceledAt / completedAt / ongoingAt / statusUpdatedAt (Dates)
  - notes (String)
  - isArchived (Boolean)
  - archiveId -> Archive (ref)
  - DB indexes: { teacher, date } and { batch, date }

ConflictLog
  - slot1 -> TimeSlot, slot2 -> TimeSlot
  - detectedAt (Date)

DateRow
  - date (Date)
  - isArchived (Boolean)
  - archiveId -> Archive (ref)

Archive
  - name (String, e.g. "Aug 5 - Aug 10")
  - startDate (Date)
  - endDate (Date)

ActivityLog
  - user -> User, userEmail, role
  - action, method, path, statusCode
  - body, query, params, metadata (Mixed, sensitive keys stripped)


=======================================================
3. FRONTEND PAGES & FEATURES
=======================================================

/master  — Master Timetable (wide layout)
  - Full grid: columns = Branch + Batch (23 columns in fixed canonical order)
  - Column order is enforced by server/utils/batchOrder.js; locked and never changes
  - Rows = date rows from DateRow collection + any date that has a slot
  - Each cell shows multiple SlotCards (time, teacher, topic, type badge)
  - Click any cell -> SlotModal for add/edit
  - Toolbar:
    - "Archive Week" button -> archives all current dates & slots, clears the grid
    - "Download All PDFs" -> ZIP of all teacher and batch PDFs
    - "Master (Word)" -> A3 landscape DOCX of master table
    - "Master (PDF)" -> A3 landscape PDF of master table
  - Setup panel (bottom):
    - Add Branch (text input)
    - Add Batch (branch select + name input)
    - Add Date Row (date picker)
    - Add Week (picks Mon-Sun from selected start date)
  - MasterGrid component handles: slot grouping by date, conflict badge overlay,
    exact-time-overlap highlighting

SlotModal (used in MasterGrid)
  - Fields: date, start time, end time, teacher (searchable), batch,
    slot type, topic, subject, chapter number, notes, status
  - Conflict detection runs on save (pre-check API + inline ConflictBanner)
  - Can cancel a slot with a mandatory cancel note
  - Supports editing and deleting existing slots

/teacher  — Teacher Timetable
  - TeacherSearchSelect to pick a teacher
  - TeacherView: shows that teacher's slots in a date-grouped table
  - Export buttons: Download PDF, Download DOCX for that teacher
  - Supports archive navigation (view past archived timetables)

/teacher-setup  — Teacher Management
  - Full CRUD for teachers (name, subject, code, color, allowScheduleOverlap toggle)
  - Per-teacher chapter list: add / edit / delete chapters with plannedHours
  - "Chapter Completion" modal: mark a chapter as complete for a specific branch or batch

/batch  — Batch Timetable
  - BatchView: branch + batch searchable selects
  - Shows that batch's slots in a date-grouped table
  - Export buttons: Download PDF, Download DOCX for that batch
  - Supports archive navigation

/tracking  — Chapter Tracking
  - ChapterTrackingPage: shows per-teacher chapter progress across all branches/batches
  - Uses chapterProgress.js utility to compute completion %
  - Visual progress bar per chapter per branch/batch

/tests  — Test Tracking
  - TestTrackingPage: lists test slots and tracks pass/fail progress
  - TestSlotModal for creating test-type slots
  - Uses testProgress.js utility for analytics

/history  — Archived Timetables
  - HistoryPage: lists all Archive records (name, date range)
  - Click an archive -> view its master grid, teacher/batch views in read-only mode
  - Can delete an archive (deletes all linked DateRows and TimeSlots)

/manage  — Branch & Batch Setup
  - ManagePage: delete branches and batches with confirmation
  - Slot deletion is only available inside SlotModal on the master grid

/admin/users  — Admin User Management (admin role only)
  - AdminPage (users tab): lists all users (no passwords shown)
  - Create user: email, name, password, role
  - Delete user (cannot delete own account)

/admin/activity  — Admin Activity Logs (admin role only)
  - AdminPage (activity tab): paginated activity log
  - Shows user, action, method, path, status code, timestamp
  - Body/query payloads truncated to 200 chars to prevent data leaks

4. BACKEND API ROUTES
=======================================================

Public (no auth):
  GET  /                          Health check -> { status: "ok" }
  POST /api/auth/login            Login (rate-limited: 10/15min per IP)
  POST /api/auth/signup           Disabled (403) - admin-only user creation
  GET  /api/auth/me               Verify JWT session, return current user

All routes below require Bearer JWT token:

Slots:
  GET    /api/slots               Fetch all active slots (populates teacher + batch + branch)
  GET    /api/slots?archiveId=X   Fetch slots for a specific archive
  POST   /api/slots               Create slot (conflict-checked)
  PUT    /api/slots/:id           Update slot (conflict-checked)
  DELETE /api/slots/:id           Delete slot
  POST   /api/slots/check-conflict  Pre-check for conflict (used by SlotModal)

Teachers:
  GET    /api/teachers                                 List all teachers (supports ?search=)
  POST   /api/teachers                                 Create teacher (auto-generates code)
  PATCH  /api/teachers/:id                             Update name / subject / allowScheduleOverlap
  DELETE /api/teachers/:id                             Delete teacher
  PATCH  /api/teachers/:id/chapters                    Add chapter to teacher
  PATCH  /api/teachers/:id/chapters/:chapterId         Edit chapter (number / title / hours)
  DELETE /api/teachers/:id/chapters/:chapterId         Delete chapter
  PATCH  /api/teachers/:id/chapters/:chapterId/branch-completion
                                                       Mark chapter complete for branch or batch

Branches:
  GET    /api/branches            List all branches
  POST   /api/branches            Create branch
  DELETE /api/branches/:id        Delete branch

Batches:
  GET    /api/batches             List all batches (sorted in canonical column order)
  POST   /api/batches             Create batch
  DELETE /api/batches/:id         Delete batch

Dates:
  GET    /api/dates               List active date rows
  POST   /api/dates               Add a single date row
  POST   /api/dates/week          Add Mon-Sun for a given start date
  DELETE /api/dates/:date         Delete date row

Timetable views:
  GET    /api/timetable/teacher/:teacherId   Teacher's slots (active or archive)
  GET    /api/timetable/batch/:batchId       Batch's slots (active or archive)

Conflicts:
  GET    /api/conflicts           List all logged conflict records

Archives:
  GET    /api/archives            List all archive records
  POST   /api/archives            Create archive (locks current dates + slots, clears active)
  DELETE /api/archives/:id        Delete archive and its linked data

Export (generates files on-demand):
  GET    /api/export/teacher/:id/pdf    Teacher timetable PDF
  GET    /api/export/teacher/:id/docx   Teacher timetable DOCX
  GET    /api/export/batch/:id/pdf      Batch timetable PDF
  GET    /api/export/batch/:id/docx     Batch timetable DOCX
  GET    /api/export/master/pdf         Master timetable PDF (A3 landscape)
  GET    /api/export/master/docx        Master timetable DOCX (A3 landscape)
  GET    /api/export/all-pdfs           ZIP of all teacher + batch PDFs

Admin (requires admin role + adminLimiter 100/min):
  GET    /api/admin/users         List all users (no passwordHash)
  POST   /api/admin/users         Create user (email, password min 8 chars, name, role)
  DELETE /api/admin/users/:id     Delete user (cannot self-delete)
  GET    /api/admin/logs          Paginated activity log (max 100 per page)


=======================================================
5. CONFLICT DETECTION LOGIC
=======================================================

- On POST/PUT /api/slots (and check-conflict), two checks run in parallel:
  1. Teacher conflict: same teacher, same date, overlapping time window
     - If teacher.allowScheduleOverlap = true, exact same-time slots are allowed
       (useful for teachers who teach the same slot in two batches simultaneously)
     - Canceled slots are excluded from conflict checks
  2. Batch conflict: same batch, same date, overlapping time window
- If any conflict is found, a 409 response is returned with conflict details
- After successful save, conflicts are also logged to ConflictLog collection
- Frontend shows a ConflictBanner inside SlotModal with conflicting slot details


=======================================================
6. SLOT STATUS AUTO-MANAGEMENT
=======================================================

- Status derives from current time vs slot time window (slotStatusService.js):
  - now < startTime  -> "scheduled"
  - startTime <= now < endTime -> "ongoing"
  - now >= endTime   -> "completed"
  - "canceled" is never overwritten
- On GET /api/slots, the server syncs statuses in bulk (bulkWrite) if derived
  status differs from stored status
- Status timestamps (ongoingAt, completedAt, canceledAt) are recorded on each transition

=======================================================
8. ARCHIVE SYSTEM
=======================================================

- "Archive Week" from the master page calls POST /api/archives
- All current DateRow records get isArchived=true, archiveId=<new archive id>
- All current TimeSlot records get isArchived=true, archiveId=<new archive id>
- A new Archive record is created with name="{startDate} - {endDate}"
- The master grid then shows empty (no active dates/slots)
- /history page lists all archives; clicking one shows its read-only timetable
  using ?archiveId= query param on timetable endpoints
- Deleting an archive permanently deletes all its linked DateRows and TimeSlots

9. EXPORT SYSTEM
=======================================================

PDF (Puppeteer):
  - masterTemplate.js generates HTML for the full master table (A3 landscape)
  - teacherTemplate.js generates HTML for per-teacher timetable
  - batchTemplate.js generates HTML for per-batch timetable
  - Puppeteer headless Chrome renders the HTML to a PDF buffer
  - exportAllPdfs uses Archiver to stream a ZIP of all teacher+batch PDFs

DOCX (docx library):
  - docxService.js builds Word documents with proper tables, borders, fonts
  - Master DOCX is A3 landscape with ultra-narrow margins (1mm)
  - Teacher and batch DOCX are standard portrait A4

File delivery:
  - All exports set Content-Disposition: attachment with filename
  - X-Content-Type-Options: nosniff header is set on all file responses
  - Export route sanitizes ID parameters (alphanumeric only, max 64 chars) to
    prevent path-traversal attacks in filenames


=======================================================
10. SECURITY
=======================================================

Authentication & Authorization
  - JWT access tokens (HS256, 2-hour expiry), only sub + role embedded (no PII)
  - JWT_SECRET validated at startup (minimum 32 chars), server exits if missing
  - Tokens stored in localStorage; sent as Bearer header on every request
  - Token refresh: app calls GET /api/auth/me on startup to validate stored token
  - Self-signup permanently disabled (POST /api/auth/signup returns 403)
  - All /api/* routes require valid JWT (authenticate middleware applied globally)
  - Role-based access: requireRole("admin") guards all /api/admin/* routes
  - Admin routes show only if user.role === "admin" in the UI (visibleRoutes filter)

Password Security
  - Passwords hashed with bcryptjs, cost factor 12
  - Minimum length 8 characters enforced at login and user creation
  - Constant-time dummy hash comparison prevents user-enumeration via timing attack
  - Login error is always generic: "Invalid email or password" (no "user not found")

Rate Limiting (express-rate-limit)
  - Login:  10 attempts / 15 minutes per IP (loginLimiter)
  - API:    300 requests / 1 minute per IP (apiLimiter on all /api/* routes)
  - Admin:  100 requests / 1 minute per IP (adminLimiter on /api/admin/* routes)
  - Uses ipKeyGenerator to correctly handle IPv4-mapped IPv6 addresses
  - Standard RateLimit-* headers returned; X-RateLimit-* legacy headers disabled
  - trust proxy = 1 set so real client IP is used (not Render proxy IP)

NoSQL Injection Prevention
  - express-mongo-sanitize applied globally before all route handlers
  - Strips $ and . from req.body, req.query, req.params (replaced with "_")
  - Prevents payloads like { "$gt": "" } from bypassing auth or enumerating data

HTTP Security Headers (Helmet)
  - X-Powered-By: removed
  - X-Frame-Options: DENY (clickjacking protection)
  - X-Content-Type-Options: nosniff
  - Strict-Transport-Security: max-age=31536000; includeSubDomains; preload (1 year HSTS)
  - Referrer-Policy: strict-origin-when-cross-origin
  - Content-Security-Policy:
      default-src 'self'
      script-src  'self'
      style-src   'self' 'unsafe-inline'
      img-src     'self' data: blob:
      font-src    'self' https://fonts.gstatic.com
      connect-src 'self'
      frame-src   'none'
      object-src  'none'
      upgrade-insecure-requests

CORS
  - Origin allowlist: process.env.CLIENT_URL + https://time-table-guru.netlify.app
  - Localhost (5173, 3000) allowed only in non-production environments
  - Requests with no Origin header blocked in production
  - credentials: true for cookie/auth header support

Body Parsing
  - JSON body size limited to 50kb (prevents payload-based DoS)
  - URL-encoded body size limited to 50kb

Input Validation & Sanitization
  - express-validator used in slots route (date, time format, slotType, status enums)
  - All string inputs trimmed and length-bounded in every route handler
  - Duplicate check for teacher names is case-insensitive (regex with $regex $options:i)
  - Regex special chars escaped before use in DB queries (escapeRegex helper)
  - Export route sanitizes URL params: /[^a-zA-Z0-9_-]/g removed, max 64 chars

Activity Logging
  - Every authenticated request triggers recordActivity() on response finish
  - Logs: user id, email, role, action, method, path, statusCode, durationMs, IP
  - Sensitive keys (password, token, secret, key, hash, etc.) are stripped from
    logged body/query before storage (sanitizeValue recursive filter)
  - Login events are explicitly logged as action "auth.login"
  - Activity logs are accessible only to admin role via GET /api/admin/logs
  - Log payloads are truncated to 200 chars in API responses to prevent data leaks
  - Non-fatal: log write failure does not crash the request

Error Handling
  - globalErrorHandler middleware converts all unhandled errors to clean JSON
  - Stack traces and internal error messages never sent to the client
  - 500 responses always return generic: "An unexpected error occurred"
  - asyncHandler wrapper used in all route handlers to pass async errors to next()

Client-Side Security
  - 401 response dispatches "auth:logout" event -> clears token, shows login screen
  - All API calls include Authorization header automatically via Axios interceptor
  - Axios interceptor retries localhost requests against production Render URL if
    local server is offline (graceful dev fallback, not a security concern)

12. HOW TO RUN LOCALLY
=======================================================

Backend:
  cd server
  cp .env.example .env            # Fill in MONGO_URI, PORT, CLIENT_URL, JWT_SECRET
  npm install
  node seed.js                    # Seeds branches and batches
  npm start                       # Starts on PORT (default 4000)

Frontend:
  cd client
  cp .env.example .env            # Set VITE_API_URL=http://localhost:4000
  npm install
  npm run dev                     # Starts Vite dev server on http://localhost:5173

Note: If VITE_API_URL is not set and the page is served from a non-localhost
origin, the client automatically connects to the production Render API.
If the local server is down, Axios will fall back to the production API.

14. NOTABLE IMPLEMENTATION DETAILS
=======================================================

- Teacher code auto-generated from name initials (e.g. "Amit Sharma" -> "AS")
  with numeric suffix if duplicate (AS, AS1, AS2...)
- Teacher color auto-assigned random hex if not provided
- Batch column order is fixed in server/utils/batchOrder.js and applied to:
  GET /api/batches, exportMasterPdf, exportMasterDocx, and exportAllPdfs
- Time values stored in "HH:MM" format (normalizeTimeFields pre-save hook)
- Slots fetch on GET /api/slots auto-syncs statuses (scheduled/ongoing/completed)
  using a bulk Mongoose write so DB stays current without a cron job
- Archiver pinned to v5.3.2 for zip stream compatibility
- All /api/export/* IDs sanitized to [a-zA-Z0-9_-] only (path-traversal prevention)
- Activity log body/query sanitization uses recursive key-blacklist, not regex,
  to correctly strip nested sensitive fields
